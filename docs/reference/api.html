API reference#

The package codecal has seven modules; the interface (codecal.gui) builds on them and adds nothing numerical. Read them in this order — each starts with a docstring that explains the concept it implements.

codecal — reliability-based calibration of partial factors, written to be read.

Modules:

distributions   Normal / Lognormal / Gumbel from mean and CoV; u → x transform
variables       RandomVariable with characteristic value; time-variant loads
reliability     FORM (HL-RF), SORM (Breitung), Monte Carlo, importance sampling
model           FailureMode, VariableLoad, DesignSituation, design equations,
                the sweep over design situations (evaluate)
calibrate       the objective Σ w (β − β_t)² and its SLSQP minimisation
spec            the model as a plain dictionary: validation, build, JSON save/load
ahg2021         the AHG "Reliability Background of the Eurocodes" model as data
plots           figures for the lessons and reports
gui             the Streamlit application (streamlit run app.py)

codecal.distributions#

Probability distributions used in code calibration.

Three families cover the whole AHG model: Normal (self-weights, permanent loads), Lognormal (resistances, model uncertainties) and Gumbel (yearly or 50-year maxima of wind, snow and imposed loads).

Every distribution is created from its mean and coefficient of variation — the way probabilistic models are tabulated in the JCSS Probabilistic Model Code — and offers the four operations the reliability methods need:

ppf(p) fractile (quantile), e.g. the 5 % fractile of a strength cdf(x) distribution function x_of_u(u) the iso-probabilistic transform x = F⁻¹(Φ(u)) dx_du(u) its derivative (chain rule for the gradient in u-space)

FORM works in the space of independent standard-normal variables u; the transform x_of_u maps a point of that space back to the physical variable, one variable at a time (the variables of the calibration model are independent, so no Nataf/Rosenblatt transformation is needed).

Gumbel (type I largest) distribution F(x) = exp(−exp(−a (x − b))).

Mean μ = b + γ/a, standard deviation σ = π/(a √6).

The distribution of the maximum over T₂ periods of a Gumbel variable that describes the maximum over one period T₁ is again Gumbel with the same a (same σ) and b shifted by ln(T₂/T₁)/a — see over_period. This is how a yearly-maximum wind load becomes the 50-year maximum.

codecal.variables#

Random variables of the calibration model and their characteristic values.

A RandomVariable bundles a name, a distribution and the characteristic value x_k that the design equation uses for it. All variables of the AHG model are normalised: the mean of a resistance, a model uncertainty, a self-weight or a 50-year load maximum is 1.0, and the characteristic value is expressed in the same units (e.g. x_k = 0.83 for steel strength means “the characteristic value is 83 % of the mean”). Partial factors therefore act on ratios, which is exactly what a calibration is about.

Characteristic values come from three sources:

  • a fractile of the distribution (5 % for strengths, 98 % of the yearly maximum for climatic loads, 50 % = mean for permanent loads);

  • a value pinned by the modeller (steel 0.83, model uncertainties 1.0);

  • for time-variant loads, a Monte-Carlo fractile of the product of the load and its model uncertainty — see time_variant_load.

codecal.variables.characteristic_value_mcs(theta_Q: RandomVariable, Q_basic: Gumbel, fractile, n=10000000, rng=None)[source]#

Fractile of the product Θ_Q · Q by Monte-Carlo simulation.

The characteristic value of a climatic load in the Eurocodes is a fractile of the yearly maximum (98 %), but the structure sees the load and the model uncertainty of its effect; the AHG defines the characteristic value on the product. There is no closed form for the fractile of a lognormal × Gumbel product, hence the simulation.

Draw order (lognormal first, then uniform → Gumbel) and the sorted-index fractile follow the 2021 implementation so that seeded runs reproduce the published numbers.

codecal.reliability#

Reliability methods: FORM, SORM, crude Monte Carlo and importance sampling.

Everything here works on a LimitState: a function g(x) of independent random variables, failure for g ≤ 0. The methods operate in the space of standard-normal variables u, reached variable by variable through x_i = F_i⁻¹(Φ(u_i)) (RandomVariable.x_of_u).

FORM (first-order reliability method)

finds the design point u*, the point of the failure surface g(u) = 0 closest to the origin. Its distance β = ‖u*‖ is the reliability index and P_f ≈ Φ(−β). The unit vector α = u*/β holds the sensitivities: α_i² is the share of variable i in the total uncertainty at the design point (Σ α_i² = 1), and the sign tells whether the variable acts as a resistance (α_i < 0) or a load (α_i > 0).

The iteration is the Hasofer–Lind / Rackwitz–Fiessler (HL-RF) scheme: linearise g at u_k, step to the design point of the linearised surface, repeat:

α_k     = −∇g(u_k)/‖∇g(u_k)‖
u_{k+1} = [α_k·u_k + g(u_k)/‖∇g(u_k)‖] α_k
SORM (second-order, Breitung 1984)

corrects P_f for the curvature of the failure surface at u*: P_f ≈ Φ(−β) Π_i (1 + β κ_i)^(−1/2), κ_i the main curvatures. For the product-type limit state of code calibration FORM is on the unsafe side by a few hundredths in β; SORM removes most of that.

Monte Carlo

draws u ~ N(0, I) and counts failures. Needs ~100/P_f samples for a 10 % standard error — millions for β ≈ 4. Importance sampling centred at the FORM design point needs a few thousand instead.

codecal.model#

The calibration problem: failure modes, loads, design situations.

A code calibration asks: which partial factors make the reliability of structures designed with the code closest to the target, over the range of structures the code is used for? Three things define that range here:

Failure modes (FailureMode)

one per material and mechanism — steel bending, concrete compression, glulam bending, … Each has a resistance model uncertainty Θ_R, a material strength R with its partial factor γ_M, the self-weight G of that material, a range of load ratios and a weight (how common it is).

Variable loads (VariableLoad)

wind, snow, imposed — each with its model uncertainty Θ_Q, the time-variant load Q (Gumbel maximum over the reference period), the combination factor ψ₀ and a weight.

Load ratios

a_Q = share of the variable load in the total characteristic load, a_G = share of the self-weight G in the permanent part (the rest is the other permanent load P). Every (mode, load, a_G, a_Q) is one design situation with weight w_mode · w_load / (n_aG · n_aQ).

The limit state of one design situation is

g = z · Θ_R · R − Θ_E · [ (1 − a_Q)(a_G G + (1 − a_G) P) + a_Q Θ_Q Q ]

where z is the design parameter: the resistance the engineer provides when designing with the code, obtained from the design equation with the characteristic values and the partial factors. All variables have mean 1; z therefore expresses how much mean resistance the code demands per unit of mean load, and the reliability index of the situation follows from the scatter of the seven variables around that ratio.

codecal.calibrate#

Calibration: choose the partial factors that bring the reliability of all design situations as close as possible to the target.

Objective (reliability-based, the AHG choice):

M(γ) = Σ_k w_k (β_k(γ) − β_t)²

over the design situations k with weights w_k (Σ w_k = 1). It is minimised with SLSQP (sequential least squares) under simple bounds. Each objective evaluation runs FORM for every situation, so a calibration with the full AHG model (810 situations) takes a minute or two.

free names the parameters the optimiser may vary; everything else keeps its start value:

(‘gamma_G’, ‘gamma_Q’) one γ_G for all permanent load, one γ_Q (AHG “dre = 1”) (‘gamma_G’, ‘gamma_GP’, ‘gamma_Q’) separate γ for self-weight and other P (“dre = 2”) (‘gamma_G’, ‘gamma_Q:wind’, ‘gamma_Q:snow’, ‘gamma_Q:imposed’) (“dre = 3”) add ‘xi’ for the two-combination equations 8.13 / 8.14.

codecal.spec#

Model specification: the calibration model as plain data.

A spec is a dictionary (JSON-serialisable) that holds every number of a calibration model — the probabilistic model, the failure modes, the loads, the sweep settings. build_model(spec) turns it into a CalibrationModel, validate_spec(spec) lists everything that is wrong with it before any computation starts, and ahg2021.ahg_spec() is the AHG model of 2021 in this form.

Why a dictionary and not objects? So that a model can be edited in a table, saved to a file, loaded again, diffed against the default and used as a cache key — the things a GUI and a reproducible study need.

codecal.ahg2021#

The probabilistic model of the AHG “Reliability Background of the Eurocodes” calibration (input of November 2021, T. Vrouwenvelder et al.).

Every number below is data, not code: change it here (or edit the dictionary ahg_spec() returns, or the JSON the lab GUI saves), nothing else. All means are 1.0 (normalised variables), so the model is a table of coefficients of variation, characteristic values and weights.

Conventions

  • Resistance model uncertainties Θ_R may carry a bias (mean ≠ 1), their characteristic value is 1.0 by definition.

  • Material strengths: 5 % fractile, except steel and aluminium where the 2021 input pinned 0.83 / 0.85 (“fractile chosen such that the characteristic value complies with the value adopted in June 2021; was this value adopted in the AHG calculations?” — still open; the 5 % fractile with CoV 0.05 would be 0.92).

  • Self-weights: normal, characteristic value = mean or a pinned value.

  • Time-variant loads: moments of the 50-year maximum (mean 1), basic period 1 a (wind, snow) or 5 a (imposed); the characteristic value is the 98 % (99 % for imposed) fractile over the basic period of the product Θ_Q·Q, by Monte Carlo; the imposed load’s was pinned at 1.35.

  • Buckling modes of the 2021 input, not part of the default set:

    steel buckling Θ_R (1.0, 0.10), a_Q (0.2, 0.8), weight 0 glulam buckling Θ_R (1.0, 0.15), a_Q (0.3, 0.8), weight 0.02 timber buckling Θ_R (1.0, 0.15), a_Q (0.3, 0.8), weight 0.01 alu buckling Θ_R (1.0, 0.10), a_Q (0.4, 0.8), weight 0.01
